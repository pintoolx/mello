# Mello Hackathon Demo Video 錄影腳本

這份腳本用來手動錄製 `/app` 的完整產品流程，成品作為 Hackathon Demo Video。官網不放這支影片，也不內嵌其他操作錄影。

## 錄影前準備

1. 在 repository 根目錄執行 `npm install` 與 `npm run dev`。
2. 開啟 `http://localhost:3000/app`。
3. 建議錄影尺寸為 1440 × 900，瀏覽器縮放維持 100%。
4. 關閉書籤列、通知與其他分頁，滑鼠先移到畫面空白處。
5. 點右上角「重置 Demo」，確認案件狀態是「草稿」。

## 建議錄製順序（約 45–60 秒）

### 00:00–00:08｜交代任務

- 停在頁面最上方。
- 帶到案件編號、17:00 截止時間與黃色出貨決策待辦。
- 簡短捲動，讓畫面看到採購需求、公司統編、成本中心與預算上限。

建議旁白：「風險人員要在今天五點前決定是否出貨。Agent 收到的採購需求，先被整理成公司、預算、核准門檻與發票條件。」

### 00:08–00:18｜執行採購

- 點「執行採購任務」。
- 等候約 2 秒，不要連續點擊。
- 將游標依序停在 GlobalData 的「拒絕」與 TaiwanRisk 的「選用」。

建議旁白：「系統拒絕更便宜但沒有台灣發票、也不在白名單的供應商，改選符合政策的 TaiwanRisk。」

### 00:18–00:30｜政策與付款

- 讓畫面停在政策檢核區約 3 秒，帶到 `ALLOW` 與六條 `PASS`。
- 向下捲至付款與交付證據表。
- 依序帶到同一 Payment ID、verify、transaction 與 service receipt。

建議旁白：「是否付款由硬規則決定，不交給 LLM。付款從 402、verify、transaction 到 receipt 都綁在同一筆邏輯請求。」

### 00:30–00:42｜發票與對帳

- 將游標停在右側三方對帳區。
- 依序帶到 `SETTLED`、`DELIVERED`、`ISSUED_TEST` 與 `MATCHED`。
- 黃色 Sandbox Invoice 提示要保留在畫面中。

建議旁白：「付款、服務交付與測試發票三方一致後，案件才會標記為 MATCHED。」

### 00:42–00:55｜重複採購攔截

- 點「模擬財務 Agent 重複下單」。
- 停在稽核事件中的 `DUPLICATE_PURCHASE · 未付款` 約 3 秒。
- 結束錄影。

建議旁白：「同一公司、同一服務與同一標的再次下單時，Mello 會攔截第二筆付款。」

## 備用錯誤路徑

正常流程錄完後可另外錄兩段短片：

- 「測試 0.03 預算」：呈現 `POLICY_DENIED · 無付款`。
- 「測試 payTo 不符」：呈現 `ADDRESS_MISMATCH · 無付款`。

每次錄新路徑前先點「重置 Demo」。
